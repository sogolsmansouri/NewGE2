Protocol:
- Raw cudaMalloc allocations, no Torch, NumPy, ctypes, or RNG dependency.
- Two buffers per device, each --bytes bytes, maximum 32 MiB per buffer;
  allocated payload memory <=64 MiB per GPU (CUDA context memory additional).
- Deterministic mixed uint32 pattern is distinct per case, never sentinel.
- Source host-to-device initialization, device synchronization and exact
  source readback are checked before each copy.
- Destination sentinel initialization is synchronized and checked exactly.
- Each copy is followed by explicit synchronization on both GPUs and exact
  source/destination readback. Every CUDA return code is emitted as JSONL.
- H2D/D2H, same-device D2D, and explicit CPU-staged controls run both ways.
- Peer synchronous calls test both current devices; peer async calls test
  both source-associated and destination-associated streams.
- Default and DeviceToDevice copy kinds each have sync and async cases.
- Copies mode with two repeats expects 44 cases: 12 controls + 32 cross-GPU
  copy cases. Exit 0 means all passed, 1 means a test failed, 2 setup/usage
  error. Use an external timeout to bound CUDA/driver hangs.
- Peer-disabled copies are driver-selected routing controls; passing that
  mode does NOT establish direct P2P operation or transfer performance.
- Optional kernel-read and kernel-write modes require peer enabled. The
  first runs a load/store copy kernel on the destination GPU; the second
  runs it on the source GPU. Run each in a separate process because an
  invalid peer mapping may poison a CUDA context. API failure stops the
  remaining cases; mismatches with successful APIs allow tests to continue.
- Timings are diagnostic wall times around copies and synchronization,
  not a formal bandwidth benchmark or training-runtime prediction.
